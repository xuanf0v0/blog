# 写作指南

这份文档说明如何在这个博客里新增、组织和维护文章。

---

## 1. 新文章放在哪里

所有公开文章都放在：

```text
src/content/blog/
```

支持两种格式：

- Markdown：`.md`
- MDX：`.mdx`

如果只是普通文章，优先用 `.md`。
如果需要嵌入 Astro 组件或更灵活的内容，使用 `.mdx`。

---

## 2. 文件命名建议

建议用英文 slug 命名文件，例如：

```text
my-first-post.md
blog-structure-notes.md
writing-workflow.mdx
```

好处：
- URL 更稳定
- 兼容性更好
- 不容易因为路径编码出现问题

---

## 3. 一篇文章的最小模板

```md
---
title: '文章标题'
description: '文章摘要'
pubDate: '2026-07-02'
tags:
  - 标签1
  - 标签2
draft: false
language: 'zh-CN'
---

## 开头

正文开始。
```

---

## 4. 推荐写法

### 普通文章
适合：
- 学习笔记
- 工具记录
- 短文
- 经验总结

```yaml
featured: false
```

### 置顶文章
适合：
- 博客入口文
- 代表作
- 长期希望首页展示的内容

```yaml
featured: true
```

### 系列文章
适合：
- 教程
- 项目复盘
- 连载内容

```yaml
series: '博客搭建记录'
seriesOrder: 1
```

---

## 5. 标签怎么写

建议原则：

- 控制在 2~5 个标签
- 优先使用已有标签
- 避免同义词重复
- 尽量不要一篇文章十几个标签

例如：

```yaml
tags:
  - Astro
  - 博客
  - 写作
```

---

## 6. 草稿怎么处理

如果文章还不准备发布，可以写：

```yaml
draft: true
```

这样它不会出现在：
- 博客列表
- 标签页
- 系列页
- 归档页
- RSS

---

## 7. 什么时候用 MDX

当你需要：
- 在正文里插入 Astro 组件
- 做更复杂的展示
- 放交互按钮或提示块

才建议用 `.mdx`。

普通文章优先 `.md`，更简单稳定。

---

## 8. 写作建议

建议每篇文章至少包含：

1. 标题
2. 一句摘要
3. 2~3 个小节标题
4. 清晰的结尾或下一步

这样：
- 搜索结果更好看
- TOC 更有用
- 文章结构更清晰

---

## 9. 发布前检查

新增文章后，建议执行：

```bash
npm run dev
```

本地确认：
- 文章页正常打开
- 标签显示正常
- 系列顺序正常
- TOC 正常生成
- 搜索页能搜到内容（需 build 后）

如果要验证搜索索引，执行：

```bash
npm run build
```
